لحظة انتهاء الـ TTL هي أخطر لحظة في اليوم

Caching II: Invalidation, Stampedes, Hot Keys
1

ليه الدرس ده مهم؟

عندك endpoint GET /api/products/{id} على منتج ترند بياخد ٥٠٠ request في الثانية، متكيّش بـ IMemoryCache لمدة ٥ دقايق. الـ hit ratio ٩٩.٨٪ والـ p99 اتحسّن من ١٨٠ ملي ثانية لـ ٤ ملي ثانية. حلو. وكل ٥ دقايق بالظبط بتلاقي في الـ logs موجة timeouts لمدة تانيتين، وCPU الداتابيز بيضرب ١٠٠٪ لحظياً.

السبب مش الداتابيز ومش الكود — السبب إن المفتاح انتهى. في الـ ٤٠٠ ملي ثانية اللي بياخدها الاستعلام عشان يخلص، الـ ٢٠٠ request اللي وصلوا في نفس اللحظة كلهم لقوا الكاش فاضي، فكلهم راحوا للداتابيز بنفس الاستعلام المتطابق. ده اسمه Cache Stampede — وإنت اللي عملته في نفسك.
لو مش فاهم الدرس ده: هتفضل تزوّد الـ TTL عشان تقلل الموجات (فتبيع طزاجة من غير ما تحل المشكلة)، وهتعتمد على إبطال صريح لوحده فتعرض داتا قديمة للأبد من المسار اللي نسيته، وهتكتشف إن الكاش نفسه اتعطّل من شهرين بس محدش كان بيراقب الـ hit ratio.
2

الفكرة في صورة: جرف الانتهاء (the expiry cliff)

الكاش مش بيتدهور بالتدريج — بيقع من على جرف. طول عمر المفتاح كل الطلبات بتتخدم من الذاكرة، وفي اللحظة اللي بعد الانتهاء كل الطلبات المتوازية بتبقى miss مع بعض، لأن مفيش حد خلّص وكتب النتيجة لسه. عدد الاستعلامات المتطابقة = عدد الطلبات اللي وصلت في نافذة الحساب.

شغّل العاصفة بنفسك

اختار عدد الطلبات المتوازية والدفاع، وبعدين دوس «شغّل». بصّ على عداد الاستعلامات.

الأرقام توضيحية من سيناريو استعلام تكلفته ٤٠٠ ملي ثانية على داتابيز بتتحمّل ضغط.

4

مثال واقعي من شغلك

أ. قبل: cache-aside عادي — مفيش حاجة بتمنع التدافع

public async Task<Product?> GetAsync(int id, CancellationToken ct)
{
    var key = $"product:{id}";
    if (cache.TryGetValue(key, out Product? hit)) return hit;

    // ٢٠٠ request وصلوا هنا مع بعض → ٢٠٠ استعلام متطابق
    var p = await db.Products.FindAsync([id], ct);
    cache.Set(key, p, TimeSpan.FromMinutes(5));
    return p;
}
// p99 وقت الانتهاء ≈ 1,800 ms · استعلامات الداتابيز في الموجة: 200
فخ مشهور: cache.GetOrCreateAsync(...) في IMemoryCache مش بيقفل. لو ٢٠٠ طلب وصلوا مع بعض، الـ factory هتتنفذ ٢٠٠ مرة. الاسم بيوحي بالأمان، والسلوك لأ.

ب. بعد: قفل لكل مفتاح — واحد بس يحسب

static readonly ConcurrentDictionary<string, SemaphoreSlim> Gates = new();

public async Task<Product?> GetAsync(int id, CancellationToken ct)
{
    var key = $"product:{id}";
    if (cache.TryGetValue(key, out Product? hit)) return hit;

    var gate = Gates.GetOrAdd(key, _ => new SemaphoreSlim(1, 1));
    await gate.WaitAsync(ct);
    try
    {
            if (cache.TryGetValue(key, out hit)) return hit;   // الفحص التاني — أهم سطر

        var p = await db.Products.FindAsync([id], ct);
        cache.Set(key, p, TimeSpan.FromMinutes(5));
        return p;
    }
    finally { gate.Release(); }
}
// p99 وقت الانتهاء ≈ 420 ms · استعلامات الداتابيز في الموجة: 1

القفل لكل مفتاح مش قفل واحد للكاش كله. لو قفلت الكاش كله، المنتج رقم ٨٨ هيوقّف كل المنتجات التانية.

ج. أو خلي المكتبة تعملها: HybridCache

// Program.cs
builder.Services.AddHybridCache();

// الخدمة — حماية من التدافع built-in، وL1 في الذاكرة فوق L2 الموزّع
public ValueTask<Product?> GetAsync(int id, CancellationToken ct) =>
    cache.GetOrCreateAsync(
        $"product:{id}",
        id,
        async (state, token) => await db.Products.FindAsync([state], token),
        new HybridCacheEntryOptions
        {
            Expiration = TimeSpan.FromMinutes(5),           // L2
            LocalCacheExpiration = TimeSpan.FromSeconds(30) // L1
        },
        tags: ["products"],
        cancellationToken: ct);

// الإبطال الصريح عند الكتابة
await cache.RemoveAsync($"product:{id}", ct);
await cache.RemoveByTagAsync("products", ct);   // كل اللي اتعلّم بالـ tag ده

التركيبة الناضجة: الاتنين. إبطال صريح على الكتابات اللي إنت متحكم فيها، وTTL معقول كشبكة أمان للمسار اللي نسيته — وفيه دايماً واحد: batch job، أداة أدمن، UPDATE يدوي من زميل على الإنتاج. الـ TTL بيحدّد أقصى ضرر للمسار اللي فاتك.
خدعة المفاتيح المُرقّمة لما الإبطال صعب التعداد (قايمة مقسّمة صفحات مثلاً): خلي المفتاح products:v{version}:list:{page}. اتغيّرت حاجة؟ زوّد الـ version رقم واحد — كل الصفحات القديمة بقت غير مقروءة فوراً من غير ما تعدّها، وبتموت لوحدها بالـ TTL.
الـ jitter: لو خزّنت ١٠ آلاف مفتاح في نفس اللحظة بنفس الـ TTL، هيخلصوا كلهم في نفس اللحظة كمان. خلي المدة TimeSpan.FromMinutes(5) + TimeSpan.FromSeconds(Random.Shared.Next(60)) عشان توزّع الانتهاء بدل ما يبقى جرف واحد.

هـ. الـ hot keys والـ big keys في Redis

منتج مشهور بيتقري ٥٠ ألف مرة في الثانية بيركّز الحمل كله على shard واحد — باقي الكلستر فاضي والواحد ده بيختنق. الحل العملي: طبقة L1 في ذاكرة كل instance بمدة قصيرة (٣٠ ثانية) تمتص الموجة قبل ما توصل Redis، أو نسخ للقراءة key:1..N وتقرا من واحدة عشوائي. وخلي القيم صغيرة: قايمة ٥ ميجا متسلسلة في مفتاح واحد بتوقّف Redis اللي بيشتغل بخيط واحد — استخدم hash وفيه fields بدل بلوك واحد عملاق.

مقياس أو مفيش: راقب الـ hit ratio لكل كاش. أقل من ٨٠٪ على مسار قرائي معناه TTL غلط، أو مفاتيح غلط، أو بتكيّش حاجة مش بتتقري. وراقب كمان حجم الكاش وعداد الـ evictions — دول اللي بيقولولك إن ضغط الذاكرة عطّل الكاش بتاعك في صمت.
5

غلطات بتحصل كتير

  • الاعتماد على الإبطال الصريح لوحده — بيفترض إنك عارف كل مسار كتابة دلوقتي وللأبد. من غير TTL، أول مسار نسيته بيسيب داتا غلط في الكاش لأجل غير مسمى.
  • افتراض إن GetOrCreateAsync بيقفل — في IMemoryCache مش بيقفل، الـ factory بتتنفذ لكل miss متوازي. الحماية موجودة في HybridCache مش في الـ IMemoryCache.
  • قفل عام بدل قفل لكل مفتاح — بتحوّل التدافع لطابور: مفتاح واحد بطيء بيوقّف كل القراءات في التطبيق.
  • نسيان الفحص التاني بعد أخد القفل — الـ ٢٠٠ طلب هيدخلوا واحد ورا التاني وكل واحد هيضرب الداتابيز، فتبقى حوّلت ٢٠٠ استعلام متوازي لـ ٢٠٠ استعلام متسلسل — أبطأ مش أسرع.
  • زيادة الـ TTL كعلاج للتدافع — ده بيقلل عدد الموجات بس مبيقللش حجم الموجة، وبتدفع التمن داتا أقدم. العلاج هو القفل أو التجديد الاستباقي، مش المدة.
6

اختبر نفسك

1. الـ cache stampede هو:
جرف الانتهاء بيحوّل مفتاح سخن واحد لـ N استعلام متزامن. القفل لكل مفتاح أو التجديد الاستباقي بيفرد الموجة دي.
2. ليه بنجمع TTL مع الإبطال الصريح بدل الإبطال الصريح لوحده؟
الإبطال المثالي معناه إنك عارف كل مسار كتابة للأبد. الـ TTL بيحدّد أقصى ضرر للمسار الوحيد اللي فاتك.
7

الخلاصة في ٣ نقاط

  1. إبطال صريح على الكتابات اللي بتتحكم فيها + TTL كشبكة أمان للمسار اللي نسيته — الاتنين مع بعض مش واحد.
  2. لحظة انتهاء مفتاح سخن = N استعلام متطابق؛ قفل لكل مفتاح (أو HybridCache) بيخليهم استعلام واحد.
  3. المفتاح السخن بيركّز الحمل على shard واحد — امتصّه بـ L1 محلي، وراقب الـ hit ratio عشان تعرف إن الكاش لسه شغال أصلاً.
