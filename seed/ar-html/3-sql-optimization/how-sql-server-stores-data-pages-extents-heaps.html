SQL Server مبيقراش صفوف — بيقرا صفحات ٨ كيلوبايت

How SQL Server Stores Data: Pages, Extents, Heaps
1

ليه الدرس ده مهم؟

عندك endpoint في ASP.NET Core بيرجّع تقرير من جدول Orders فيه مليون صف. الصف عرضه ٣٨٠ بايت تقريباً، يعني بيدخل في الصفحة الواحدة ٢١ صف بس → الجدول قاعد في حوالي ٤٧ ألف صفحة. الاستعلام بيقرا الـ ٤٧ ألف كلهم ويخلص في ٤٠٠ ملي ثانية. زميلك غيّر SELECT * لعمودين جايين من فهرس مغطّي — نفس الصفوف بالظبط، بس صف الفهرس ١٦ بايت → ٤٤٩ صف في الصفحة → ٢٢٣١ صفحة بس.

الفكرة كلها: التكلفة مش عدد الصفوف، التكلفة عدد الصفحات. SQL Server عمره ما قرا «صف» — بيقرا صفحة ٨ كيلوبايت كاملة وياخد اللي عايزه منها. أي تحسين بتعمله في حياتك، في الآخر بيقلل عدد الصفحات المقروءة.
لو مش فاهم الدرس ده: هتقيس التحسين بالوقت (اللي بيتغير مع الكاش والضغط على السيرفر) بدل الـ logical reads، هتصمّم صفوف عريضة من غير سبب فتضاعف تكلفة كل scan في الجدول، وهتسيب جداول الـ Logs بتاعتك heaps ومتفهمش ليه القراءات بتتضاعف مع الوقت.
2

الفكرة في صورة: جوّه الصفحة الواحدة

الصفحة فيها header ثابت ٩٦ بايت، وبعده الصفوف بتتحط ورا بعضها، وفي آخر الصفحة slot array بيقول كل صف بيبدأ عند أنهي بايت (٢ بايت لكل صف). فاضل للصفوف ≈ 8096 بايت.

عشان كده أقصى صف ≈ 8060 بايت. لو عندك nvarchar(max) أو varbinary(max) وكبر عن كده، القيمة بتتشال off-row في صفحات LOB والصف بيمسك مؤشر ليها — يعني قراءة زيادة كل مرة تطلب العمود ده.
3

خطوة بخطوة: عمر جدول heap

الـ heap = جدول من غير clustered index. الصف بيتحط في أول صفحة فيها مكان، من غير أي ترتيب. دوس «التالي» وبصّ على العدادات، وبعدين جرّب الأزرار بنفسك.

مثال واقعي: اقرا الأرقام بنفسك

أ. قيس بالصفحات مش بالثواني

SET STATISTICS IO ON;

-- الجدول كله: الصف ≈ 380 بايت → 21 صف في الصفحة
SELECT * FROM Orders WHERE OrderDate >= '2025-01-01';
-- Table 'Orders'. logical reads 47,620     ← 400 ms

-- نفس الصفوف من فهرس مغطّي: صف الفهرس ≈ 16 بايت → 449 صف في الصفحة
SELECT OrderId, OrderDate FROM Orders WHERE OrderDate >= '2025-01-01';
-- Table 'Orders'. logical reads 2,231      ← 18 ms
الـ logical reads رقم ثابت بيوصف شغل الخطة نفسها. الوقت بيتغير مع الكاش والضغط والجهاز — فأي مقارنة «قبل/بعد» اعملها بالـ logical reads.

ب. شوف الصفحات بعينك على قاعدتك

-- كام صفحة كل جدول واخد؟
SELECT t.name, p.rows, au.data_pages, au.data_pages * 8 / 1024.0 AS size_mb
FROM sys.tables t
JOIN sys.partitions p ON p.object_id = t.object_id AND p.index_id IN (0,1)
JOIN sys.allocation_units au ON au.container_id = p.partition_id
WHERE au.type = 1;

-- الـ heap بيعمل forwarding pointers ولا لأ؟ (index_id = 0 يعني heap)
SELECT forwarded_record_count, avg_page_space_used_in_percent
FROM sys.dm_db_index_physical_stats(DB_ID(), OBJECT_ID('Logs'), 0, NULL, 'DETAILED');

-- العلاج: رصّ الصفحات من تاني أو حطّ clustered index
ALTER TABLE Logs REBUILD;

5

غلطات بتحصل كتير

  • قياس التحسين بالوقت — تشغيل أول (cold cache) مقابل تاني (warm) بيدوك رقمين مختلفين لنفس الخطة. SET STATISTICS IO ON والـ logical reads هو المقياس اللي مبيكدبش.
  • سيبان جدول بيتحدّث كتير heap — كل UPDATE بيوسّع صف بيسيب forwarding pointer مكانه، فكل قراءة للصف ده بقت قراءتين. راكم مع الوقت لحد ما القراءات تتضاعف.
  • «الجدول صغير، ٢٠٠ ألف صف بس» — العبرة بعدد الصفحات. ٢٠٠ ألف صف عرضه ٢ كيلوبايت = ٦٦ ألف صفحة = نص جيجا في البفر بول.
  • nvarchar(4000) لكل عمود نصي «احتياطي» — العرض المحجوز بيقلل عدد الصفوف في الصفحة، فكل scan في الجدول بيغلى للأبد. استخدم الطول اللي محتاجه فعلاً.
  • استخدام SELECT * وبعدين الشكوى إن الفهرس مش بيتستخدم — الأعمدة الزيادة بتخلي الفهرس المغطّي مش مغطّي، فيرجع للجدول العريض ويقرا صفحاته كلها.
6

اختبر نفسك

1. صف عرضه ٤٠٥٠ بايت — كام صف بيقعد في الصفحة الواحدة؟
المتاح للصفوف = 8192 − 96 (header) = 8096، وكل صف بياخد 2 بايت كمان في الـ slot array. اتنين = 8104 > 8096 → صف واحد، ونص الصفحة ضايع.
2. أدق مقياس تقارن بيه نسختين من نفس الاستعلام:
الوقت بيتغير مع الكاش والضغط والهاردوير؛ الـ logical reads بتقيس الشغل اللي الخطة بتعمله فعلاً وثابتة بين التشغيلات.
7

الخلاصة في ٣ نقاط

  1. وحدة التخزين والقراءة هي الصفحة ٨ كيلوبايت، و٨ صفحات = extent = وحدة الحجز — فتكلفة أي استعلام بعدد الصفحات مش الصفوف.
  2. عرض الصف بيحدد كام صف يقعد في الصفحة، وده بيحدد حجم الجدول وتكلفة كل scan عليه للأبد.
  3. الـ heap بيتبعتر بالـ forwarding pointers مع التحديثات — قيس بـ logical reads وحطّ clustered index أو اعمل REBUILD.
