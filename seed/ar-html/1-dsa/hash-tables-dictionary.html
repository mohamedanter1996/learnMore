الـ Dictionary بيلاقي المفتاح في خطوة واحدة — إزاي؟

Hash Tables: How Dictionary<TKey,TValue> Works
1

ليه الدرس ده مهم؟

عندك ٥٠ ألف Order و٥٠ ألف Payment، وعايز تطابقهم. لو كتبتها كده: payments.FirstOrDefault(p => p.OrderId == o.Id) جوّه لوپ على الأوردرات — إنت عملت ٢.٥ مليار مقارنة. نفس الشغل بـ Dictionary بيخلص في أقل من ثانية.

الفكرة: بدل ما ندوّر عنصر عنصر، بنحسب من المفتاح نفسه رقم (hash) بيقولنا مكانه على طول. الوصول بقى O(1) في المتوسط بدل O(n).
لو مش فاهمه: هتكتب O(n²) وإنت فاكرها لوپ عادية، وهتستخدم كلاس كمفتاح من غير Equals/GetHashCode فالبحث يرجع فاضي «من غير سبب».

مثال واقعي من شغلك

// ❌ O(n²) مخفي — 50k × 50k = 2.5 مليار مقارنة
foreach (var o in orders) {
    var p = payments.FirstOrDefault(x => x.OrderId == o.Id);
    ...
}

// ✅ فهرسة مرة واحدة → بحث O(1)
var byOrder = payments.ToDictionary(x => x.OrderId);   // مرة واحدة O(n)
foreach (var o in orders) {
    if (byOrder.TryGetValue(o.Id, out var p)) ...      // بحث واحد بس
}

المفتاح المخصص: العقد اللي لازم تحترمه

// ✅ record: Equals + GetHashCode بيتولدوا صح أوتوماتيك
public record ProductKey(int WarehouseId, string Sku);

// ❌ class عادي: المقارنة بالمرجع → مش هتلاقي المفتاح أبداً
public class BadKey { public int Id; }
dict[new BadKey { Id = 5 }] = ...;
dict[new BadKey { Id = 5 }];   // KeyNotFoundException — مرجع مختلف
القاعدة: مفتاحين متساويين لازم يدّوا نفس الـ hash. والمفتاح لازم يبقى ثابت بعد ما تحطه — لو غيّرت قيمة داخلة في الـ hash، العنصر بيضيع جوّه الـ dictionary. 
// مقارنة نصوص من غير حساسية لحالة الحروف — من غير أي تخصيص زيادة
var byName = new Dictionary<string, User>(StringComparer.OrdinalIgnoreCase);

// ❌ بحثين على نفس المفتاح
if (dict.ContainsKey(k)) { var v = dict[k]; ... }
// ✅ بحث واحد
if (dict.TryGetValue(k, out var v)) { ... }

غلطات بتحصل كتير

  • تعديل المفتاح بعد الإضافة — الـ hash بيتغير فالعنصر يبقى في bucket غلط ومبيتلاقاش.
  • كلاس كمفتاح من غير Equals/GetHashCode — المقارنة بالمرجع. استخدم record أو نفّذهم بنفسك.
  • hash ضعيف (مثلاً بيرجع رقم ثابت) — كل العناصر في bucket واحد، والبحث يرجع O(n).
  • ContainsKey وبعدها الـ indexer — بحثين بدل واحد. TryGetValue أنضف وأسرع.
  • الاعتماد على ترتيب العناصر — الـ Dictionary مالوش ترتيب مضمون؛ لو محتاج ترتيب استخدم SortedDictionary أو رتّب وقت العرض.
  • نسيان السعة الابتدائية — new Dictionary<K,V>(expectedCount) بيمنع عمليات resize متكررة.
6

اختبر نفسك

1. مفتاحين مختلفين طلعوا نفس رقم الـ bucket. إيه اللي بيحصل؟
ده اسمه collision — طبيعي جداً. الـ hash بيحدد الـ bucket، والـ Equals هو اللي بيحسم المفتاح الصح.
2. متى يتحوّل بحث الـ Dictionary لـ O(n)؟
O(1) متوسط بيعتمد على توزيع كويس. hash ثابت أو ضعيف = سلسلة واحدة طويلة = بحث خطي.
7

الخلاصة في ٣ نقاط

  1. الـ hash بيحوّل المفتاح لمكان مباشر: hash % size → bucket، فالوصول O(1) في المتوسط.
  2. التصادم طبيعي: الـ bucket بيشيل سلسلة، والـ Equals بيحدد المفتاح الصح.
  3. أي Contains/FirstOrDefault جوّه لوپ = فهرسه مرة واحدة في Dictionary/HashSet وخلاص.
