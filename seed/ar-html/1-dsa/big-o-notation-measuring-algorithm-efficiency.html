Big-O مش بتقيس السرعة — بتقيس إنت هتتعور إمتى

Big-O Notation: Measuring Algorithm Efficiency
1

ليه الدرس ده مهم؟

عندك endpoint في ASP.NET Core بيطابق الأوردرات بالشحنات: 8,000 أوردر و8,000 شحنة. كتبتها كده: 

foreach (var o in orders)
    o.Shipment = shipments.FirstOrDefault(s => s.OrderId == o.Id);

على بيئة الـ dev عندك ٢٠٠ أوردر — الصفحة بتفتح في ٣٠ ملي ثانية، تمام. على الـ production بـ ٨٠٠٠ أوردر بقت ٤.٢ ثانية. الداتا كبرت ٤٠ مرة بس عدد المقارنات كبر ١٦٠٠ مرة: من 200 × 200 = 40,000 لـ 8,000 × 8,000 = 64,000,000. السبب إن FirstOrDefault جوه foreach بيلف على الليست من أولها لكل أوردر.

الـ Big-O بتجاوب على سؤال واحد بس: لو الداتا بقت الضعف، الشغل هيزيد أد إيه؟ مش بنقيس بالثواني — الثواني بتختلف من جهاز لجهاز. بنقيس شكل النمو، والشكل ده هو اللي بيحدد هل الكود هيعيش لما الداتا تكبر ولا هيموت.
لو مش فاهم الدرس ده: هتسلّم كود شغّال تمام على الـ dev وبيقع على الـ production، وهتقعد تحسّن حاجات مش مهمة (تشيل if من جوه loop) وسايب الـ O(n²) اللي هو السبب الحقيقي، وهتفضل تقول «السيرفر ضعيف» والمشكلة في ٣ سطور كود.
2

الفكرة في صورة: شكل النمو

المحور الأفقي = حجم الداتا n. المحور الرأسي = عدد العمليات، ولوغاريتمي — كل خطوة لفوق معناها ×1000، وإلا الـ O(n²) كانت هتطلع بره الشاشة من بدري. حرّك الشريط وشوف الأرقام بتتغير.

4

مثال واقعي من شغلك

أ. المطابقة بين ليستين — الغلطة الأشهر

❌ O(n²) — بحث جوه لفّة
foreach (var o in orders)          // n
    o.Shipment = shipments
        .FirstOrDefault(s => s.OrderId == o.Id);  // n

// n = 8,000 → 64,000,000 مقارنة ≈ 4,200 ms
// (المقارنة عبر delegate في LINQ أغلى بكتير من عملية بسيطة)
✅ O(n) — فهرس مرة واحدة
var byOrder = shipments
    .ToDictionary(s => s.OrderId);        // n مرة واحدة

foreach (var o in orders)              // n
    if (byOrder.TryGetValue(o.Id, out var s))  // O(1)
        o.Shipment = s;

// n = 8,000 → 16,000 عملية ≈ 3 ms

١٤٠٠ ضعف من غير ما تلمس السيرفر ولا الداتابيز. ده الـ rewrite اللي هتعمله أكتر من أي حاجة تانية: loop جوه loop → Dictionary/HashSet.

ج. قواعد الحساب — تلاتة بس

// 1) حاجات ورا بعضها → خد الأكبر
Sort(arr);                     // O(n log n)
foreach (var x in arr) Print(x);  // O(n)
// الإجمالي = O(n log n)  مش O(n log n + n)

// 2) حاجة جوه حاجة → اضرب
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)  // نص المصفوفة بس… برضه O(n²)
        Compare(arr[i], arr[j]);

// 3) الثوابت بتتشال
// 3n + 100  →  O(n)        نفس الشكل، بس مزحلق لفوق
// n² / 2    →  O(n²)       القسمة على 2 مبتغيّرش الشكل
ومعاها الـ space complexity: الـ ToDictionary فوق كلّفتك O(n) ذاكرة زيادة. ده اسمه space-time trade-off، وهو اختيار صريح — بتدفع رام عشان تكسب وقت. بنحسب الذاكرة الزيادة بس، مش الداتا الداخلة نفسها.
5

غلطات بتحصل كتير

  • ‏Contains / Any / FirstOrDefault جوه loop — الـ O(n²) المخفية. مفيش loop تانية ظاهرة فبتعدّي في الـ review. لو الليست اللي بتدوّر فيها ثابتة، حوّلها HashSet أو Dictionary قبل اللفّة.
  • ‏list.Insert(0, x) أو string += جوه loop — كل عملية O(n) لوحدها لأنها بتنسخ كل حاجة، فاللفّة كلها O(n²) وإنت شايف سطر واحد. استخدم Add + Reverse أو StringBuilder.
  • نسيان إن مش كل «عملية» زي التانية — O(n) فيها استعلام داتابيز لكل عنصر (مشكلة N+1 في EF Core) أبطأ بكتير من O(n²) في الرام. الـ Big-O بتعد العمليات، مش بتقول إن العملية تمنها كام.
  • تحسين الـ Big-O وn بتاعتك ٢٠ — على أرقام صغيرة الثوابت هي اللي بتحكم، ولفّة بسيطة على array بتكسب Dictionary بكل الـ hashing اللي فيه. قيس الأول، وبعدين حسّن.
  • الحكم بالحالة المتوسطة — احسب الأسوأ إلا لو قلت غير كده صراحةً. قيمة O(1) بتاعة الـ Dictionary دي متوسط؛ لو الـ GetHashCode وحش بتبقى O(n) فعلاً.
6

اختبر نفسك

1. ميثود فيها لفّة O(n)، وبعدها لفّة متداخلة O(n²). التعقيد الإجمالي؟
الحاجات اللي ورا بعضها بناخد الحد المسيطر بس: O(n) + O(n²) = O(n²). الضرب بيحصل في التداخل، مش في التتابع.
2. foreach (var x in a) if (b.Contains(x)) … والاتنين List<int> بحجم n. التعقيد وإزاي تصلّحه؟
‏List.Contains بحث خطي = O(n)، وجوه لفّة O(n) يبقى O(n²). تحويل b لـ HashSet مرة واحدة تكلفته O(n) وبيخلي كل بحث O(1) → الإجمالي O(n).
7

الخلاصة في ٣ نقاط

  1. Big-O بتوصف شكل النمو لما n تكبر — بترمي الثوابت والحدود الصغيرة، عشان دي هي الحاجة الوحيدة اللي بتفضل صح مهما اتغيّر الجهاز.
  2. ورا بعضها = خد الأكبر، جوه بعضها = اضرب، والأسوأ هو المقياس إلا لو قلت غير كده.
  3. بحث جوه لفّة هو الـ O(n²) اللي هتقابلها أكتر من أي حاجة — وDictionary/HashSet قبل اللفّة بتحوّلها O(n) مقابل ذاكرة زيادة.
