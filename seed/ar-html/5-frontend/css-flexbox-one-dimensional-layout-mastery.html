CSS Flexbox: One-Dimensional Layout Mastery
1

ليه الدرس ده مهم؟

عندك جدول في Angular بيعرض Orders، عرض الشاشة ٩٦٠ بكسل، وكل صف display: flex. جه عميل إيميله ٧٨ حرف من غير أي مسافة، وفجأة الصفحة كلها بقى فيها سكرول أفقي: عرض المحتوى طلع ١٨٤٠ بكسل بدل ٩٦٠، والـ header الثابت بقى مقصوص. مفيش أي حاجة اتغيرت في الـ CSS — اتغيّرت الداتا بس.

السبب مش bug في المتصفح: عنصر الـ flex الافتراضي min-width: auto، يعني بيرفض يضغط تحت حجم محتواه الأدنى. الـ flex-shrink بيوصل لحد الأرضية دي ويقف. الحل سطر واحد: min-width: 0 على العنصر.
لو مش فاهم الدرس ده: هتفضل تحل مشاكل الـ layout بـ width: 33% و position: absolute و!important، وهتكتب justify-content: center وانت عايز توسيط رأسي فتستغرب ليه مش شغال، وهتشحت في الـ overflow اللي بيظهر مع داتا حقيقية بس.
2

الفكرة في صورة: محورين، مش أربع اتجاهات

الـ flex container ليه محور رئيسي (main axis) بتترصّ عليه العناصر، ومحور عرضي (cross axis) عمودي عليه. justify-* بيشتغل على الرئيسي وalign-* على العرضي. flex-direction بيبدّل مين فيهم مين — وده مصدر اللخبطة كله.

📐 عرض الحاوية: 420px ↔️ عرض المحتوى الفعلي: — 🩹 الحالة: min-width: auto (الافتراضي) 
/* ❌ العمود بيرفض يضغط تحت طول النص → سكرول أفقي في الصف كله */

نفس القصة بالظبط في flex-direction: column بس بـ min-height: 0 — من غيرها العنصر اللي المفروض يعمل overflow-y: auto بيمدّد الصفحة كلها بدل ما يعمل سكرول جوّه نفسه.

ب. أعمدة متساوية بجد: flex: 1 مقابل flex: 1 1 auto

✅ basis صفر — المحتوى ملوش لازمة
.col { flex: 1; }   /* = 1 1 0% */
// حاوية 900px، محتوى 100/300/200
// النتيجة: 300 / 300 / 300
❌ basis auto — المحتوى الأكبر بياخد أكتر
.col { flex: 1 1 auto; }
// نفس الحاوية ونفس المحتوى
// النتيجة: 200 / 400 / 300

الاتنين بيوزّعوا الـ ٣٠٠ بكسل الزيادة بالتساوي — الفرق إن الأول بدأ من صفر فالتوزيع هو كل الحكاية، والتاني بدأ من حجم المحتوى فالفروق فضلت موجودة.

ج. Navbar وكارت بفوتر ثابت

/* logo شمال، أزرار يمين — من غير أي عرض ثابت */
.nav    { display: flex; align-items: center; gap: 12px; }
.spacer { flex: 1; }                 /* أو margin-inline-start: auto على الأزرار */

/* كارت الفوتر بتاعه دايماً تحت مهما كان الجسم قصير */
.card      { display: flex; flex-direction: column; height: 100%; }
.card-body { flex: 1; min-height: 0; overflow-y: auto; }
ملاحظة RTL مهمة: في صفحة dir="rtl" الـ flex-direction: row بيمشي من اليمين للشمال لوحده. متستخدمش row-reverse عشان تعدّلها — ده بيكسر ترتيب الـ DOM للـ keyboard وللـ screen readers. استخدم flex-start/flex-end وmargin-inline-start وسيب الاتجاه للمتصفح.
5

غلطات بتحصل كتير

  • «justify-content: center مش بيوسّط رأسي» — طبعاً، هو بيشتغل على المحور الرئيسي. في row التوسيط الرأسي شغلانة align-items.
  • نسيان min-width: 0 — أشهر gotcha في الـ CSS كله. أي نص طويل أو <pre> أو جدول جوّه flex item بيفيض بدل ما يضغط.
  • flex-grow: 1 لوحده وانت عايز أعمدة متساوية — الـ basis فضل auto، فالمحتوى الأكبر بياخد عمود أعرض. اكتب flex: 1.
  • margins بين العناصر بدل gap — وبعدين حيلة :last-child عشان تشيل آخر واحدة. gap مدعوم في الـ flexbox في كل المتصفحات الحالية.
  • استخدام flex لهيكل صفحة بُعدين بـ flex-wrap وwidth: 33% — الأعمدة مش بتتحاذى بين الصفوف. ده شغل Grid، مش Flexbox.
6

اختبر نفسك

1. نص طويل من غير مسافات جوّه flex item بيفيض برّه الحاوية. ليه؟
دي قاعدة الحد الأدنى الضمني (implicit minimum size). الـ shrink بيقف عندها، وmin-width: 0 (أو overflow: hidden) بيلغيها.
2. flex: 1 1 0 على كل الأبناء بيدي أعمدة متساوية. ليه بالظبط؟
مع basis: auto المحتوى الأكبر = عمود أعرض. الـ basis صفر بيصفّر المطالبة المبدئية، فأوزان الـ grow لوحدها هي اللي بتقرر.
7

الخلاصة في ٣ نقاط

  1. اسأل «المحور الرئيسي دلوقتي أنهي؟» — justify-* عليه وalign-* على اللي عموده.
  2. flex: grow shrink basis هي التفاوض كله: الـ basis نقطة البداية، والـ grow بيوزّع الزيادة، والـ shrink بيوزّع العجز مضروب في الـ basis.
  3. أي overflow غريب في flex → جرّب min-width: 0 (أو min-height: 0 في العمود) قبل أي حاجة تانية.
