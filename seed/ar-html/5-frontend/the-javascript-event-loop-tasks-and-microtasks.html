خيط واحد بس — والتزامن كله ترتيب طوابير

The JavaScript Event Loop: Tasks and Microtasks
1

ليه الدرس ده مهم؟

شاشة في Angular بتجيب ٥٠ ألف صف من /api/orders وبعدين بتفلترهم وبترتّبهم جوه الـ component. الـ endpoint بيرجع في ١٢٠ ملي ثانية، بس المستخدم بيقولك «الصفحة بتهنج ثانية كاملة». تفتح تبويب Performance تلاقي كتلة صفرا واحدة طولها ٩٠٠ ملي ثانية — task واحد طويل. في التسعمية دول: مفيش render، الـ spinner واقف، الـ click مش بيوصل، وحتى الـ console.log اللي جوه setTimeout(fn, 0) مستني في الطابور.

JavaScript بيشتغل بـ thread واحد. الـ event loop بيعمل نفس اللفّة على طول: نفّذ task للآخر ← فضّي طابور الـ microtasks كله ← يمكن render ← الـ task اللي بعده. مفيش «خلفية» إلا لو إنت عملتها: تسيب الخيط (await / تقسيم على tasks) أو تطلع بره (Web Worker).
لو مش فاهم الدرس ده: هتـ«تصلّح» الهنج بإنك تلف الحسبة التقيلة في setTimeout(fn, 0) — نفس الـ task الطويل بس اتأجل، والهنج زي ما هو. وهتستغرب ليه Promise.then بيسبق setTimeout(fn, 0)، وليه الـ await «مش بيستنى»، وليه Angular بيعمل change detection في لحظات غريبة (zone.js بيعمل patch للـ APIs دي بالظبط).
2

الفكرة في صورة: اللفّة نفسها

الترتيب مش رأي — هو مواصفة. setTimeout(fn, 0) معناه «حطّ fn في طابور الـ tasks بعد ٠ ملي ثانية على الأقل»، مش «نفّذه حالاً». وطابور الـ microtasks بيتفضّى كله — لو microtask جابت microtask تانية، دي كمان بتتنفّذ في نفس الدورة قبل أي رسم.

4

جرّب بنفسك: احجز الخيط أو سيبه

العداد اللي تحت بيعدّ إطارات حقيقية بـ requestAnimationFrame. دوس الأحمر تشوف النبضة بتقف فعلاً، ودوس الأخضر تشوفها ماشية وإحنا بنعمل نفس الشغل بالظبط.

🎞 إطارات آخر ثانية: 0 ⛔ أطول task: 0 ms ✅ الشغل المنجز: 0 / 60

كل عمود = إطار. الأعمدة الحمرا = فترة اللي المتصفّح مرسمش فيها حاجة. نفس عدد العمليات في الحالتين — الفرق إنك سيبت الخيط بين الدفعات.

5

مثال واقعي من شغلك

أ. Angular: فلترة ٥٠ ألف صف جوه الـ component

❌ task واحد طويل — هنج ٩٠٠ ms
async load() {
  const rows = await firstValueFrom(
      this.api.orders());        // 120 ms شبكة
  const out: Row[] = [];
  for (const r of rows) out.push(score(r));
  this.rows.set(out);
  // أطول task = 900 ms → مفيش render ولا click
}
✅ مقسّم على tasks — أطول task ١٤ ms
async load() {
  const rows = await firstValueFrom(
      this.api.orders());
  const out: Row[] = [];
  for (let i = 0; i < rows.length; i++) {
    out.push(score(rows[i]));
    if (i % 500 === 0)
      await new Promise(r => setTimeout(r));
  }
  this.rows.set(out);
  // نفس المدة الكلية ~950 ms، بس الشاشة حيّة
}
خُد بالك: await new Promise(r => setTimeout(r)) بيسيب task — وده اللي بيخلي المتصفح يرسم. أما await Promise.resolve() فبيسيب microtask بس، والـ render مش بيحصل بين الـ microtasks. غلطة شايعة جداً.

ب. الـ await مش بيوقف الخيط

async function f() {
  console.log('a');
  await null;            // كل اللي بعد ده = microtask continuation
  console.log('c');
}
f();
console.log('b');
// → a, b, c   الدالة رجّعت عند الـ await، والباقي اتجدول

ج. الشغل التقيل بجد: Web Worker

// worker.ts — thread تاني، مفيش DOM ومفيش window
addEventListener('message', e => postMessage(heavy(e.data)));

// الـ component
const w = new Worker(new URL('./worker', import.meta.url), { type: 'module' });
w.onmessage = e => this.rows.set(e.data);   // الرسالة بترجع كـ task عادي
w.postMessage(rows);                        // النقل نفسه بيتكلف (structured clone)
قاعدة عملية: لو الشغل أقل من ~٥٠ ms سيبه زي ما هو. من ٥٠ لـ ٥٠٠ ms قسّمه على tasks. فوق كده وبيتكرر — Worker. وفي Angular لو حسبة مالهاش لازمة تولّع change detection، شغّلها بـ NgZone.runOutsideAngular وارجع بـ run لما تخلص.
6

غلطات بتحصل كتير

  • «setTimeout(fn, 0) معناه فوراً» — معناه «بعد ما الـ task الحالي يخلص وكل الـ microtasks تتفضّى». وبعد ٥ مستويات متداخلة المتصفح بيثبّته على ٤ ms كحد أدنى.
  • لف الحسبة التقيلة في setTimeout وخلاص — الـ task لسه طوله ٩٠٠ ms، بس اتأخر شوية. التقسيم هو الحل، مش التأجيل.
  • «الـ await بيوقف التنفيذ» — الدالة بترجع عند أول await، والباقي بيتجدول كـ microtask. الكود اللي بعد نداء الدالة بيشتغل قبله.
  • تجويع الرسم بـ microtasks — loop بتعمل queueMicrotask أو .then جوه نفسها بتمنع الـ render للأبد، لأن الطابور لازم يفضى قبل الرسم. لو محتاج loop مستمر استخدم requestAnimationFrame أو setTimeout.
  • قياس بالحس بدل DevTools — تبويب Performance: أي كتلة فوق ٥٠ ms هي jank حقيقي. وفي Angular، طول الـ task بيشمل الـ change detection اللي اتسببت منه.
7

اختبر نفسك

1. Promise.resolve().then(A); setTimeout(B, 0); — مين يشتغل الأول بعد ما الـ script الحالي يخلص؟
طابور الـ microtasks بيتفضّى بالكامل بعد الـ task الحالي، وsetTimeout مستني في طابور الـ tasks وراه — مهما كان التأخير ٠.
2. عايز المتصفح يرسم في نص لفّة طويلة. تسيب الخيط بإيه؟
الأولانيين microtasks — بيتفضّوا في نفس الدورة والرسم مبيحصلش بينهم. الـ setTimeout بيسيب task حقيقي، والـ render بيحصل بين الـ tasks.
8

الخلاصة في ٣ نقاط

  1. خيط واحد بينفّذ كل task للآخر — فأي كود sync طويل بيجمّد الرسم والأحداث كلها، مش شاشتك بس.
  2. الـ microtasks (.then وawait) بتتفضّى بالكامل بعد كل task وقبل الرسم، فهي دايماً بتسبق setTimeout(fn, 0).
  3. تسيب الخيط بـ task (setTimeout) عشان يرسم، وتطلع بره بـ Web Worker لما الشغل يبقى تقيل بجد.
